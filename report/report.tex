\section{Introduction}
This report documents a scalar reverse-mode automatic differentiation engine (\texttt{src/engine.py}) and a small neural-network API built on top of it (\texttt{src/nn.py}), following the design of Karpathy's \emph{micrograd}. Every number in the system is wrapped in a \texttt{Value} node that stores its \texttt{data}, its gradient \texttt{grad}, the set of nodes it was computed from (\texttt{\_prev}) and a closure \texttt{\_backward} that pushes gradient to those nodes.

\section{The Computational Graph}
Evaluating an expression builds a directed acyclic graph (DAG): every operator creates a new \texttt{Value} whose \texttt{\_prev} are its operands. The loss $L$ is the root of this graph. Backpropagation computes $\partial L/\partial v$ for every node $v$.

\subsection{Local derivatives}
Let $\bar v \equiv \partial L / \partial v$ and let $o$ be the output of an operation. By the chain rule each operand receives $\bar{x} \mathrel{+}= \frac{\partial o}{\partial x}\,\bar o$. The local rules implemented are:

\begin{center}
\begin{tabular}{lll}
\hline
Operation & Forward & Backward (accumulated into operands) \\
\hline
Addition & $o = a + b$ & $\bar a \mathrel{+}= \bar o,\quad \bar b \mathrel{+}= \bar o$ \\
Multiplication & $o = a\,b$ & $\bar a \mathrel{+}= b\,\bar o,\quad \bar b \mathrel{+}= a\,\bar o$ \\
Power (constant $k$) & $o = a^{k}$ & $\bar a \mathrel{+}= k\,a^{k-1}\,\bar o$ \\
Tanh & $o = \tanh a$ & $\bar a \mathrel{+}= (1-o^{2})\,\bar o$ \\
Exponential & $o = e^{a}$ & $\bar a \mathrel{+}= o\,\bar o$ \\
\hline
\end{tabular}
\end{center}

\paragraph{Derivation of $\tanh'$.} With $\tanh x = \frac{e^{x}-e^{-x}}{e^{x}+e^{-x}}$, the quotient rule gives
\[
\frac{d}{dx}\tanh x = \frac{(e^{x}+e^{-x})^{2}-(e^{x}-e^{-x})^{2}}{(e^{x}+e^{-x})^{2}} = 1-\tanh^{2}x .
\]
Reusing the already-computed output $o=\tanh x$ makes the backward pass free of extra transcendental calls.

\paragraph{Derived operators.} Negation is $-a = a\cdot(-1)$, subtraction is $a-b = a+(-b)$, and division is $a/b = a\cdot b^{-1}$. Because these are composed from the primitives above, their gradients follow automatically. For division this gives $\partial(a/b)/\partial a = 1/b$ and $\partial(a/b)/\partial b = -a/b^{2}$, since $\frac{d}{db}b^{-1} = -b^{-2}$.

\subsection{Why gradients are accumulated with \texttt{+=}}
If a variable is used more than once, the total derivative is the \emph{sum} over all paths from the variable to the loss (multivariate chain rule). Take $c = a + a$, $d = c\cdot a$ at $a=3$:
\[
d = 2a^{2} \;\Rightarrow\; \frac{\partial d}{\partial a} = 4a = 12 .
\]
Through the graph, $a$ receives $\bar c\cdot 1 + \bar c \cdot 1 = 2a$ via the two operands of $c$ and $c\cdot 1 = 2a = 6$ via the direct product edge, which totals $6+6=12$. Using \texttt{=} instead of \texttt{+=} would overwrite earlier contributions and give a wrong answer, which is exactly what the diamond-graph test checks.

\section{Topological Sort and \texttt{backward()}}
A node's gradient is complete only after \emph{all} nodes that consume it have run their \texttt{\_backward}. A topological order of the DAG, in which every node appears after all of its operands, reversed, guarantees this.

\begin{lstlisting}
def _get_topo(self):
    topo, visited = [], set()
    def build_topo(node):
        if node not in visited:
            visited.add(node)
            for child in node._prev:
                build_topo(child)
            topo.append(node)      # post-order: after the children
    build_topo(self)
    return topo

def backward(self):
    topo = self._get_topo()
    self.grad = 1.0                # dL/dL = 1
    for node in reversed(topo):
        node._backward()
\end{lstlisting}

\paragraph{Design justification.}
\begin{itemize}
  \item \textbf{Post-order append.} Appending a node \emph{after} visiting its children places every operand before the nodes that use it; reversing then processes consumers first. Appending before the loop (pre-order) can process a node before its consumers have contributed, so its gradient would be propagated while still incomplete.
  \item \textbf{The \texttt{visited} set.} In a diamond graph a node is reachable by several paths. Without the set it is appended multiple times, so \texttt{\_backward} would run repeatedly and double-count gradient; in deep networks the number of paths is exponential, so the traversal would also be exponentially slow. Because nodes are hashed by identity (no \texttt{\_\_eq\_\_} is defined), the set tracks object identity, not value equality.
  \item \textbf{Closures.} Each operator captures its operands and its output in a closure, so \texttt{backward()} needs no knowledge of operator types.
  \item \textbf{Scalar promotion and type safety.} Binary operators wrap plain \texttt{int}/\texttt{float} operands in a \texttt{Value}, and return \texttt{NotImplemented} for any other type so that Python raises \texttt{TypeError} (e.g.\ \texttt{Value(2.0) + "s"}). The reflected versions (\texttt{\_\_radd\_\_}, \texttt{\_\_rmul\_\_}) make \texttt{2.0 + a} work.
  \item \textbf{Power restricted to constants.} \texttt{\_\_pow\_\_} asserts the exponent is \texttt{int} or \texttt{float}; the rule $k\,a^{k-1}$ is only valid when the exponent is a constant. Division by a zero-valued \texttt{Value} naturally raises \texttt{ZeroDivisionError} from Python's $0.0^{-1}$.
\end{itemize}

\subsection{Worked example}
For $f = (ab)(a+b)$ with $a=-2$, $b=3$ we have $f = a^{2}b + ab^{2}$, so
\[
\frac{\partial f}{\partial a} = 2ab + b^{2} = -12+9 = -3, \qquad
\frac{\partial f}{\partial b} = a^{2} + 2ab = 4-12 = -8,
\]
which is what the engine returns.

\section{The Neural Network API}
\begin{itemize}
  \item \textbf{Neuron.} For $n_{in}$ inputs it holds weights $w_i\sim\mathcal U(-1,1)$ and a bias $b\sim\mathcal U(-1,1)$, all \texttt{Value}s. It computes $y=\tanh\!\big(\sum_i w_i x_i + b\big)$ and has $n_{in}+1$ parameters.
  \item \textbf{Layer.} A list of \texttt{nout} neurons sharing the same input; it returns a single \texttt{Value} when \texttt{nout}$=1$, otherwise a list.
  \item \textbf{MLP.} Layers of sizes $[n_{in}, n_1,\dots,n_k]$ applied sequentially. A single-output layer in the middle of the network is wrapped in a list before being fed to the next layer.
  \item \textbf{Parameters and \texttt{zero\_grad}.} \texttt{parameters()} flattens all weights and biases. \texttt{zero\_grad()} must be called before each \texttt{backward()} in a training loop, otherwise gradients from earlier steps accumulate (because of \texttt{+=}).
\end{itemize}
For \texttt{MLP(3,[4,4,1])} the parameter count is $(3\cdot4+4)+(4\cdot4+4)+(4\cdot1+1)=16+20+5=41$.

\section{Conceptual Questions}
\paragraph{Why use reverse mode rather than forward mode?}
A neural network has many parameters and one scalar loss. Reverse mode obtains the gradient with respect to all parameters in a single backward sweep with cost proportional to one forward pass, while forward mode needs one sweep per parameter.

\paragraph{Why must \texttt{zero\_grad} be called?}
The backward rules accumulate into \texttt{grad}. Without resetting, the gradient of step $t$ would include that of steps $1,\dots,t-1$.

\paragraph{Why can the neurons ``die''?}
When $|z|$ is large, $\tanh$ saturates, $1-\tanh^{2}z\approx 0$, and the gradient vanishes. The \texttt{p.grad != 0.0} test in \texttt{test\_nn.py} therefore assumes the $\mathcal U(-1,1)$ initialisation does not saturate every unit.

\begin{itemize}

\section{Conclusion}
A complete reverse-mode autodiff engine needs only the local derivative of each primitive, gradient accumulation, and a topological ordering of the graph. The same machinery that powers the 41-parameter network here is conceptually the one used by PyTorch, only vectorised over tensors.
