\section{Overview}

The goal is a reverse-mode automatic differentiation engine that works on single scalars, together with a small neural network API built on top of it. Every arithmetic operation on a \texttt{Value} creates a new node that remembers its inputs and the operation that produced it. Calling \texttt{backward()} on the final node walks this graph in reverse and applies the chain rule at every node, so each leaf ends up holding $\partial L / \partial \text{leaf}$.

The code is split into two files, as required by the template:
\begin{itemize}
  \item \texttt{src/engine.py}: the \texttt{Value} class, its operators, the activations \texttt{tanh} and \texttt{exp}, and the topological-sort backward pass.
  \item \texttt{src/nn.py}: \texttt{Neuron}, \texttt{Layer} and \texttt{MLP}.
\end{itemize}

\section{The Computational Graph}

\subsection{The \texttt{Value} node}

Each node stores:
\begin{itemize}
  \item \texttt{data}: the scalar computed in the forward pass.
  \item \texttt{grad}: $\partial L/\partial(\text{this node})$, starting at $0$.
  \item \texttt{\_prev}: the set of input nodes (children in the graph).
  \item \texttt{\_op}: a string naming the operation, used for inspection.
  \item \texttt{\_backward}: a closure that moves this node's gradient into its children.
\end{itemize}

For a node $z = g(x_1, \dots, x_k)$, the chain rule gives the contribution of $z$ to each input:
\begin{equation}
  \frac{\partial L}{\partial x_i} \mathrel{+}= \frac{\partial g}{\partial x_i} \cdot \frac{\partial L}{\partial z}.
\end{equation}
The term $\partial L/\partial z$ is \texttt{out.grad}, and $\partial g/\partial x_i$ is the \emph{local derivative}, which depends only on the operation. Each \texttt{\_backward} closure implements exactly this line for one operation.

\subsection{Local derivatives}

\paragraph{Addition.} $z = x + y$:
\[
  \frac{\partial z}{\partial x} = 1, \qquad \frac{\partial z}{\partial y} = 1
  \;\Rightarrow\; x.\text{grad} \mathrel{+}= z.\text{grad},\quad y.\text{grad} \mathrel{+}= z.\text{grad}.
\]
Addition passes the gradient through unchanged to both inputs.

\paragraph{Multiplication.} $z = xy$:
\[
  \frac{\partial z}{\partial x} = y, \qquad \frac{\partial z}{\partial y} = x
  \;\Rightarrow\; x.\text{grad} \mathrel{+}= y \cdot z.\text{grad},\quad y.\text{grad} \mathrel{+}= x \cdot z.\text{grad}.
\]
Each input's gradient is scaled by the value of the other input.

\paragraph{Power by a constant.} $z = x^{n}$, $n \in \mathbb{R}$ fixed:
\[
  \frac{\partial z}{\partial x} = n\,x^{n-1}
  \;\Rightarrow\; x.\text{grad} \mathrel{+}= n\,x^{n-1} \cdot z.\text{grad}.
\]

\paragraph{Hyperbolic tangent.} $z = \tanh x = \dfrac{e^{x} - e^{-x}}{e^{x} + e^{-x}}$. By the quotient rule,
\[
  \frac{d}{dx}\tanh x
  = \frac{(e^{x}+e^{-x})^2 - (e^{x}-e^{-x})^2}{(e^{x}+e^{-x})^2}
  = 1 - \tanh^2 x,
\]
so $x.\text{grad} \mathrel{+}= (1 - z^2)\cdot z.\text{grad}$. The derivative is written in terms of the output $z$, which is already stored, so no extra exponentials are computed in the backward pass.

\paragraph{Exponential.} $z = e^{x}$:
\[
  \frac{d}{dx} e^{x} = e^{x} = z \;\Rightarrow\; x.\text{grad} \mathrel{+}= z \cdot z.\text{grad}.
\]

\subsection{Derived operations}

The remaining operators are built from the ones above, so they need no backward code of their own:
\begin{align*}
  -x &= x \cdot (-1), \\
  x - y &= x + (-y), \\
  x / y &= x \cdot y^{-1}.
\end{align*}
For division the gradient follows automatically: $\partial(x y^{-1})/\partial y = x \cdot (-1)\,y^{-2} = -x/y^{2}$, which is the quotient rule. Dividing by zero raises \texttt{ZeroDivisionError} because Python refuses to compute $0.0^{-1}$.

The reflected operators \texttt{\_\_radd\_\_}, \texttt{\_\_rmul\_\_}, \texttt{\_\_rsub\_\_} and \texttt{\_\_rtruediv\_\_} handle expressions such as \texttt{2.0 + a}, where the plain number is on the left.

\subsection{Type handling}

A helper \texttt{toValue} wraps \texttt{int} and \texttt{float} operands in a \texttt{Value} and raises \texttt{TypeError} for anything else. So \texttt{Value(2.0) + "string"} and \texttt{Value(2.0) * [1, 2, 3]} fail immediately with a clear message, instead of failing later or, for the list case, silently repeating the list.

The exponent of \texttt{\_\_pow\_\_} is asserted to be an \texttt{int} or \texttt{float}. Supporting a \texttt{Value} exponent would need the extra derivative $\partial(x^{y})/\partial y = x^{y}\ln x$, which is undefined for $x \le 0$. Since the networks here only need constant powers, the engine rejects that case outright.

\section{Backpropagation with a Topological Sort}

\subsection{Why an ordering is needed}

A node's \texttt{\_backward} reads \texttt{out.grad} and pushes it into the children. That is only correct if \texttt{out.grad} is final, meaning every node that uses \texttt{out} has already sent its contribution. Visiting nodes in reverse topological order guarantees this: in a topological order every node appears after all of its inputs, so in reverse every node appears before all of its inputs.

\subsection{Building the order}

\begin{lstlisting}[language=Python]
def _get_topo(self):
    topo = []
    visited = set()

    def buildTopo(node):
        if node not in visited:
            visited.add(node)
            for child in node._prev:
                buildTopo(child)
            topo.append(node)

    buildTopo(self)
    return topo

def backward(self):
    topo = self._get_topo()
    self.grad = 1.0
    for node in reversed(topo):
        node._backward()
\end{lstlisting}

The search is a post-order depth-first search: a node is appended only after all of its children are appended. The root gets $\partial L/\partial L = 1$, and \texttt{\_backward} then runs from the root down to the leaves.

\subsection{The two traps}

\paragraph{Post-order trap.} If the node were appended \emph{before} its children are visited (pre-order), a parent could appear in the list before a node that also depends on it through another path. In the reversed list that node would then run its \texttt{\_backward} before its own gradient is complete, and the missing part would never reach the leaves.

\paragraph{Diamond trap.} Consider $a = 3$, $c = a + a$, $d = c \cdot a$. The node $a$ is reached by three paths. Without the \texttt{visited} set, $a$ would be added to \texttt{topo} several times, and its \texttt{\_backward} would run several times. That is harmless for a leaf, but if $a$ were an inner node its children would receive the same contribution more than once. With the set, every node appears exactly once.

A related requirement is that gradients are \emph{accumulated} with \texttt{+=}. For $c = a + a$, \texttt{\_prev} is the set $\{a\}$, but \texttt{\_backward} still writes to \texttt{self.grad} and \texttt{other.grad}, which are the same object. With \texttt{+=} both contributions add up:
\[
  d = 2a^{2}, \qquad \frac{\partial d}{\partial a}
  = \underbrace{c}_{\text{from }d=c\cdot a} + \underbrace{a \cdot (1 + 1)}_{\text{from }c=a+a}
  = 6 + 6 = 12 = 4a,
\]
which matches the analytic result. With plain \texttt{=} the second write would overwrite the first.

\subsection{Worked example}

For $a=-2$, $b=3$, $d = ab$, $e = a+b$, $f = de$:

\section{The Neural Network API}

\paragraph{Neuron.} A neuron with $n$ inputs holds weights $w_1,\dots,w_n$ and a bias $b$, all drawn from $\mathcal{U}(-1, 1)$, and computes
\[
  \text{out} = \tanh\!\Big(b + \sum_{i=1}^{n} w_i x_i\Big).
\]
The sum is started from $b$ (\texttt{sum(..., self.b)}), so the bias is part of the same graph and no extra addition node is needed.

\paragraph{Layer.} A list of $n_\text{out}$ independent neurons that all see the same input. When $n_\text{out}=1$ the single \texttt{Value} is returned instead of a one-element list, so a network with one output can be used directly as a loss.

\paragraph{MLP.} Given \texttt{nin} and a list \texttt{nouts}, the sizes $[\text{nin}, n_1, \dots, n_k]$ define $k$ consecutive layers; the output of each layer is the input of the next. The parameter count of a layer is $n_\text{out}(n_\text{in}+1)$, so \texttt{MLP(3, [4, 4, 1])} has $16+20+5=41$ parameters, as the tests expect.

\paragraph{Parameters and zeroing.} \texttt{parameters()} returns a flat list at every level, and \texttt{zero\_grad()} calls \texttt{reset\_grad()} on each one. Gradients must be cleared before every backward pass, because \texttt{+=} would otherwise add the new gradients onto the old ones.

\section{Design Justifications}

\begin{itemize}
  \item \textbf{Closures for \texttt{\_backward}.} Each closure captures the exact operands and output of its own operation, so the backward pass needs no lookup table or type switch.
  \item \textbf{Composite operators.} Subtraction, negation and division reuse addition, multiplication and power. There is less code to get wrong, and their gradients are correct as soon as the three base rules are.
  \item \textbf{Strict operand types.} Rejecting non-numeric operands early turns silent errors into immediate \texttt{TypeError}s.
  \item \textbf{tanh derivative from the output.} Using $1 - z^{2}$ reuses the forward result and avoids recomputing exponentials.
  \item \textbf{Recursive DFS.} It matches the specification directly. Its limit is Python's recursion depth (about 1000 by default), which is far above the depth of the graphs used here.
\end{itemize}

\section{Conceptual Questions}

\paragraph{Q1. Why is backpropagation done in reverse topological order?}
A node can only pass on its gradient once that gradient is complete. Reverse topological order processes every consumer of a node before the node itself, so each \texttt{\_backward} sees a final \texttt{out.grad}. Every node is visited once, so the backward pass costs about as much as the forward pass.

\paragraph{Q2. Why must gradients be accumulated with \texttt{+=}?}
By the multivariable chain rule, if a variable reaches the output through several paths, its derivative is the \emph{sum} of the contributions of all paths. Plain assignment keeps only the last path. The diamond graph $d = (a+a)\cdot a$ gives $6$ instead of $12$ with \texttt{=}.

\paragraph{Q3. Why do we need the \texttt{visited} set?}
In a graph where a node is shared, depth-first search reaches the same node from several parents. Without the set the node is appended once per path. The work then grows exponentially with depth, and the same \texttt{\_backward} is applied repeatedly, which counts contributions more than once.

\paragraph{Q4. Why must \texttt{zero\_grad()} be called before each backward pass?}
Because gradients are accumulated, the \texttt{grad} fields still hold the previous step's values. Without zeroing, every update would use the sum of all past gradients instead of the current one.

\paragraph{Q5. Why are weights initialised randomly instead of to zero?}
If all weights in a layer start equal, all neurons compute the same output and receive the same gradient, so they stay identical forever. Random values break this symmetry. The range $[-1, 1]$ also keeps the pre-activations of a small network inside the region where $\tanh$ is not saturated, so the gradients do not vanish.

\paragraph{Q6. How does this engine differ from PyTorch?}
The algorithm is the same: reverse mode on a dynamically built graph. The difference is granularity. PyTorch nodes operate on whole tensors with vectorised kernels, while here every scalar multiply is a separate Python object. A layer with $n_\text{in} \times n_\text{out}$ weights creates that many nodes for each sample, which is why the engine is fine for teaching but far too slow for real models.

\paragraph{Q7. Why is reverse mode used rather than forward mode?}
A neural network maps many parameters to a single scalar loss. Reverse mode gives the derivatives with respect to \emph{all} inputs in one backward pass. Forward mode would need one pass per parameter.
