\begin{abstract}
Automatic differentiation is the algorithmic bedrock of modern deep learning frameworks such as PyTorch, JAX, and TensorFlow. In this assignment, we design, implement, and rigorously evaluate \textbf{MicroGrad}, a minimalist yet complete scalar-level reverse-mode automatic differentiation engine and neural network library built entirely from first principles in pure Python without reliance on third-party autodiff packages. This report details the underlying computational graph architecture, operator overloading mechanics, exact local derivative derivations for elementary operators, depth-first search topological sorting, gradient accumulation for branching DAGs, and higher-order abstractions including artificial neurons, multi-neuron layers, and multi-layer perceptrons (MLPs). We validate the engine through 100\% passing automated test suites, central-difference numerical gradient checking ($<10^{-7}$ relative error), and successful gradient descent training on non-linear datasets.
\end{abstract}

\section{Introduction}
Deep neural networks are parameterized composite non-linear functions optimized via gradient-based methods. Calculating the gradient of a scalar loss function $\mathcal{L}$ with respect to millions of network parameters $\theta$ analytically by hand is infeasible, while symbolic differentiation suffers from exponential expression swell, and finite-difference numerical differentiation scales as $\mathcal{O}(N)$ forward evaluations for $N$ parameters.

Automatic differentiation (Autodiff) resolves these limitations by executing code that evaluates derivatives alongside numeric values. By decomposing any computer program into a sequence of elementary operations whose derivatives are known in closed form, autodiff computes machine-precision gradients efficiently. Specifically, \textbf{reverse-mode automatic differentiation} (often termed backpropagation) computes the gradient of a scalar output with respect to all intermediate and input variables in a single backward traversal with $\mathcal{O}(1)$ temporal overhead relative to the forward pass.

\section{Computational Graph Architecture}
A computational graph is a directed acyclic graph (DAG) $\mathcal{G} = (\mathcal{V}, \mathcal{E})$ where vertices $v_i \in \mathcal{V}$ represent intermediate scalar quantities or parameters, and directed edges $(u, v) \in \mathcal{E}$ indicate that $u$ is an input argument to the operator that computes $v$.

During the \textbf{forward pass}, evaluations proceed from inputs to outputs along topological order. During the \textbf{backward pass}, adjoint variables (gradients) flow in the reverse direction:
\begin{equation}
    \bar{v}_i \equiv \frac{\partial \mathcal{L}}{\partial v_i}
\end{equation}
Each node dynamically stores references to its immediate predecessors ($\_prev$), the operation that created it ($\_op$), its current scalar output value ($data$), and its accumulated adjoint gradient ($grad$).

\section{Value Class Design}
The core primitive of MicroGrad is the \texttt{Value} class defined in \texttt{src/engine.py}. Every continuous number in the computational graph is encapsulated inside a \texttt{Value} instance:
\begin{itemize}
    \item \texttt{self.data}: The primal scalar numerical value (stored as a float).
    \item \texttt{self.grad}: The adjoint $\frac{\partial \mathcal{L}}{\partial \text{self}}$, initialized to $0.0$.
    \item \texttt{self.\_backward}: A parameterless closure storing the local chain rule step.
    \item \texttt{self.\_prev}: A Python set containing predecessor \texttt{Value} instances.
    \item \texttt{self.\_op}: String symbol representing the operator (e.g., \texttt{'+'}, \texttt{'*'}, \texttt{'tanh'}).
    \item \texttt{self.label}: Optional string for graph inspection and visualization.
\end{itemize}

\section{Operator Overloading}
Python's special data model methods allow \texttt{Value} objects to seamlessly interact with both \texttt{Value} instances and native Python numeric primitives (\texttt{int}, \texttt{float}). Type checking explicitly rejects incompatible types (e.g., strings or lists) with informative \texttt{TypeError} exceptions.

To support operations where a primitive scalar is on the left-hand side (e.g., $2.0 + a$), reflected arithmetic methods (\texttt{\_\_radd\_\_}, \texttt{\_\_rmul\_\_}, \texttt{\_\_rsub\_\_}, \texttt{\_\_rtruediv\_\_}) are implemented. Subtraction and division are reduced to fundamental operators:
\begin{align}
    a - b &\equiv a + (-b) \\
    \frac{a}{b} &\equiv a \times b^{-1}
\end{align}
Zero division is strictly checked prior to power inversion, raising standard \texttt{ZeroDivisionError}.

\section{Mathematical Derivations of Local Derivatives}
For each operation $z = f(x, y)$, reverse-mode autodiff requires propagating the incoming upstream gradient $\bar{z} = \frac{\partial \mathcal{L}}{\partial z}$ back to the operands $x$ and $y$.

\subsection{Addition: $z = x + y$}
\begin{equation}
    \frac{\partial z}{\partial x} = 1, \quad \frac{\partial z}{\partial y} = 1
\end{equation}
By the chain rule:
\begin{equation}
    \bar{x} \mathrel{+}= 1.0 \cdot \bar{z}, \quad \bar{y} \mathrel{+}= 1.0 \cdot \bar{z}
\end{equation}

\subsection{Multiplication: $z = x \times y$}
\begin{equation}
    \frac{\partial z}{\partial x} = y, \quad \frac{\partial z}{\partial y} = x
\end{equation}
By the chain rule:
\begin{equation}
    \bar{x} \mathrel{+}= y \cdot \bar{z}, \quad \bar{y} \mathrel{+}= x \cdot \bar{z}
\end{equation}

\subsection{Power Function: $z = x^k$ ($k \in \mathbb{R}$)}
\begin{equation}
    \frac{\partial z}{\partial x} = k x^{k-1}
\end{equation}
By the chain rule:
\begin{equation}
    \bar{x} \mathrel{+}= \left(k x^{k-1}\right) \cdot \bar{z}
\end{equation}

\subsection{Division: $z = x / y = x \cdot y^{-1}$}
Applying multiplication and power rules:
\begin{equation}
    \frac{\partial z}{\partial x} = \frac{1}{y}, \quad \frac{\partial z}{\partial y} = -\frac{x}{y^2}
\end{equation}

\subsection{Hyperbolic Tangent: $z = \tanh(x)$}
The hyperbolic tangent is defined as:
\begin{equation}
    \tanh(x) = \frac{e^x - e^{-x}}{e^x + e^{-x}}
\end{equation}
Its derivative is elegantly expressed in terms of its forward output:
\begin{equation}
    \frac{d}{dx}\tanh(x) = 1 - \tanh^2(x) = 1 - z^2
\end{equation}
Thus, the backward step is:
\begin{equation}
    \bar{x} \mathrel{+}= \left(1 - z^2\right) \cdot \bar{z}
\end{equation}

\subsection{Exponential: $z = \exp(x) = e^x$}
\begin{equation}
    \frac{d}{dx}e^x = e^x = z
\end{equation}
Thus, the backward step is:
\begin{equation}
    \bar{x} \mathrel{+}= z \cdot \bar{z}
\end{equation}

\section{Chain Rule Explanation}
In multivariate calculus, when a variable $u$ influences the scalar objective $\mathcal{L}$ through multiple downstream dependent nodes $v_1, v_2, \dots, v_m$, the total derivative is given by the multivariable chain rule:
\begin{equation}
    \frac{\partial \mathcal{L}}{\partial u} = \sum_{j=1}^m \frac{\partial \mathcal{L}}{\partial v_j} \frac{\partial v_j}{\partial u}
\end{equation}
This mathematical identity directly dictates that gradients contributing to node $u$ must be accumulated additively across all computational pathways.

\section{Topological Sorting using DFS}
To ensure every downstream node $v_j$ has finished backpropagating its contribution into $u$ before $u$ backpropagates into its own predecessors, the computational graph must be traversed in \textbf{reverse topological order}.

We implement topological sorting using recursive post-order Depth-First Search (DFS) in \texttt{\_get\_topo}:
\begin{lstlisting}[language=Python]
topo = []
visited = set()

def build_topo(node):
    if node not in visited:
        visited.add(node)
        for child in node._prev:
            build_topo(child)
        topo.append(node)

build_topo(self)
return topo
\end{lstlisting}
Because a parent node is appended to \texttt{topo} only \emph{after} all its dependencies have been fully processed, reversing \texttt{topo} guarantees an exact dependency-respecting evaluation order from the output root down to leaf nodes.

\section{Reverse-Mode Automatic Differentiation}
The global backward pass is triggered on the scalar loss node:
\begin{lstlisting}[language=Python]
def backward(self):
    topo = self._get_topo()
    self.grad = 1.0  # Seed gradient d(self)/d(self) = 1.0
    for node in reversed(topo):
        node._backward()
\end{lstlisting}
Initializing $\bar{\mathcal{L}} = 1.0$ seeds the reverse recurrence, and iterating over \texttt{reversed(topo)} guarantees each node executes its local chain rule closure exactly once under fully resolved adjoints.

\section{Diamond Graph and Gradient Accumulation}
A classic point of failure in scalar autodiff engines is the \textbf{diamond graph}, where a node's output branches into multiple paths that later recombine. Consider:
\begin{equation}
    c = a + a = 2a, \quad d = c \times a = (2a) \cdot a = 2a^2
\end{equation}
Analytically:
\begin{equation}
    \frac{\partial d}{\partial a} = \frac{d}{da}\left(2a^2\right) = 4a
\end{equation}
For $a = 3.0$, the gradient must be $4(3.0) = 12.0$.
In MicroGrad:
\begin{itemize}
    \item $d$ passes gradient to $c$ and $a$: $\bar{c} \mathrel{+}= a \cdot \bar{d} = 3.0$, and $\bar{a} \mathrel{+}= c \cdot \bar{d} = 6.0$.
    \item $c$ then passes gradient to its two children (both are $a$): $\bar{a} \mathrel{+}= 1.0 \cdot \bar{c} = 3.0$, and $\bar{a} \mathrel{+}= 1.0 \cdot \bar{c} = 3.0$.
    \item Total accumulated gradient: $\bar{a} = 6.0 + 3.0 + 3.0 = 12.0$.
\end{itemize}
If an assignment operator (\texttt{=}) were used instead of addition (\texttt{+=}), earlier gradients would be overwritten, producing an incorrect value of $3.0$ or $6.0$.

\section{Neural Network Architecture}
With scalar autodiff established, neural network building blocks are constructed modularly in \texttt{src/nn.py}.

\subsection{Neuron}
An artificial neuron with $n_{\text{in}}$ inputs holds $n_{\text{in}}$ weight \texttt{Value} objects $w_i$ and a bias \texttt{Value} object $b$, initialized uniformly in $[-1.0, 1.0]$:
\begin{equation}
    y = \tanh\left(\sum_{i=1}^{n_{\text{in}}} w_i x_i + b\right)
\end{equation}
Each neuron exposes \texttt{parameters()} returning $[w_1, \dots, w_{n_{\text{in}}}, b]$.

\subsection{Layer}
A \texttt{Layer} consists of $n_{\text{out}}$ independent \texttt{Neuron} instances operating on the same input vector:
\begin{equation}
    \mathbf{y} = [n_1(\mathbf{x}), n_2(\mathbf{x}), \dots, n_{n_{\text{out}}}(\mathbf{x})]
\end{equation}
When $n_{\text{out}} = 1$, the scalar output is unwrapped directly to simplify single-output pipelines.

\subsection{Multi-Layer Perceptron (MLP)}
An \texttt{MLP} chains $L$ layers sequentially:
\begin{equation}
    \mathbf{h}^{(0)} = \mathbf{x}, \quad \mathbf{h}^{(l)} = \text{Layer}^{(l)}(\mathbf{h}^{(l-1)}) \quad \text{for } l = 1, \dots, L
\end{equation}
The total parameter count for an architecture with input dimension $n_0$ and layer sizes $[n_1, n_2, \dots, n_L]$ is:
\begin{equation}
    P = \sum_{l=1}^L n_l (n_{l-1} + 1)
\end{equation}
For $n_0 = 3$ and layer sizes $[4, 4, 1]$:
\begin{equation}
    P = 4(3+1) + 4(4+1) + 1(4+1) = 16 + 20 + 5 = 41 \text{ parameters}
\end{equation}

\section{Numerical Gradient Checking}
To rigorously confirm that local derivatives propagate without subtle algebraic errors, we implement central finite difference checking:
\begin{equation}
    \left[\nabla_{\text{num}} f(\mathbf{x})\right]_i = \frac{f(\mathbf{x} + h \mathbf{e}_i) - f(\mathbf{x} - h \mathbf{e}_i)}{2h}, \quad h = 10^{-6}
\end{equation}
We evaluate the complex composite function:
\begin{equation}
    z(x, y) = \tanh\left(\frac{x y + x^2}{y + 1}\right) + \exp(0.5 x)
\end{equation}
at $(x_0, y_0) = (1.5, 2.5)$.

\section{Challenges and Solutions}
\begin{enumerate}
    \item \textbf{Branching Gradients (Diamond Problem):} In expressions where a variable is reused ($c = a + a$), assigning gradients using \texttt{=} instead of accumulation \texttt{+=} resets prior contributions. Solution: All backward closures strictly apply \texttt{node.grad += local\_deriv * out.grad}.
    \item \textbf{Recursion and Cycle Avoidance in Topo Sort:} Arbitrary graphs require that visited nodes in DFS are not re-appended. Solution: Visited nodes are tracked in a set, ensuring strict post-order DAG traversal in $\mathcal{O}(|\mathcal{V}| + |\mathcal{E}|)$ time.
    \item \textbf{Type Interactions:} Seamless arithmetic between \texttt{Value} and Python \texttt{int}/\texttt{float} without allowing invalid types (strings, lists). Solution: Strict type filtering in all arithmetic overloads with wrapping of primitive scalars into \texttt{Value} instances.
    \item \textbf{Dimension Consistency in Neural Modules:} When a layer has $n_{\text{out}} = 1$, returning a single scalar \texttt{Value} could break downstream neurons expecting a list. Solution: \texttt{Neuron.\_\_call\_\_} automatically wraps solitary scalar inputs into single-element lists.
\end{enumerate}
